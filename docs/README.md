# Documentation

Four documents, in the order they are useful.

## [ARCHITECTURE.md](ARCHITECTURE.md)

The map. The system diagram, the four decisions taken before any code was written, what
each of the five tiers does, where the LLM sits and what stops it, and what the
measurements changed about how the system should be *described*.

Read this first.

## [../DECISIONS.md](../DECISIONS.md)

The territory. Every architectural decision, dated, with the alternatives rejected and what
the choice cost — 41 of them.

It is not a tidy record written afterwards. Most entries were written *because a
measurement contradicted something we believed*, and several document defects that a green
test suite did not catch. Where this and `ARCHITECTURE.md` disagree, this wins, because it
is dated.

Start with **ADR-034** if you only read one — it explains why the cascade beats an LLM-only
baseline, and the reason is not the one you would guess.

## [../results/](../results/)

Every published number, generated by `make eval` and never typed.

- **`metrics.md`** — the §9.2 ablation in full, per fixture, with the exception breakdown by
  reason code.
- **`summary.md`** — the compact table spliced into the README. A test asserts the two are
  byte-identical, and CI fails the build if either drifts.
- **`throughput.md`** — timings, deliberately outside that guarantee. A timing describes the
  machine it ran on, not the code (ADR-041).
- **`report.html`** — the run report. Open it and step a real Tier 3 adjudication through
  the gates one at a time.

## [../PROJECT_SPEC.md](../PROJECT_SPEC.md)

The original specification, unedited.

Kept as written on day one rather than revised to match what was built, so the gap between
the two is visible. Several of its assumptions turned out to be wrong — §8's claim that a
wrong fee model surfaces as an exception cluster does not hold in this cascade, and
ADR-029 explains why. Quietly editing the spec to agree with the outcome would have hidden
the most interesting thing the project found.
